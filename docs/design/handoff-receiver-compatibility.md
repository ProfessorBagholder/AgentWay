# Native receiver compatibility — Phase 0

Status: research only, 2026-09-23. **No AgentWay-to-native-agent unattended handoff is verified.** A product being able to call AgentWay's MCP server proves outbound access, not inbound delivery. The [2026-07-28 MCP specification](https://blog.modelcontextprotocol.io/posts/2026-07-28/) does not supply an unsolicited server-to-idle-agent turn; its multi-round-trip requests occur in the course of a client call. This matrix is a feasibility inventory for thin integrations against the [common AgentWay receiver protocol](handoff-receiver-contract.md); it is not a list of different handoff features or a basis for choosing a product-specific architecture. Recheck product availability and documentation at implementation time.

It is evidence for authenticated sender and recipient APIs, not receiver delivery. No publishing action is needed for the next probes.

## Gate and immediate next action

Phase 0 has **not exited**: the [universal receiver protocol](handoff-receiver-contract.md) and [reusable conformance scenario](handoff-conformance-v1.md) are defined, but no product has demonstrated unattended delivery into its intended existing agent and return to the sender. The strongest currently documented direct external trigger is the Workspace Agents API, but that is a separately configured ChatGPT product. Grok Bot's same-Bot routine and Codex's same-thread scheduled task are candidate transports only. They do not alter AgentWay's common states or release bar. The next action is to test each candidate against the same scenario with native transcript and AgentWay receipt evidence, timestamps, deduplication and return delivery. If an advertised product cannot meet that scenario, resolve product scope with the owner; do not ship a weaker handoff for it or a privileged subset by default.
