# Agent handoff contract

An AgentWay connection is an authenticated agent principal. The owner permits directed assignment from one connection ID to another on the sender's Agents detail page. No reciprocal grant is implied. Both connections must have authenticated at least once before a grant can be added. Disconnecting a connection revokes grants to and from it. Agent discovery returns only permitted active recipients; it never returns credentials, conversations or invented availability.

The sending agent creates a task with a stable `request_id` and recipient ID. An identical retry returns the saved task. A changed payload under the same ID conflicts. Task creation saves the row and event atomically. The receiving agent checks its inbox and claims a queued task with a random UUID it generated. The same claim UUID safely reconciles a lost response. Claims last five minutes; renewals extend the lease. After expiration a new claim fences the old token. Only the current recipient claim can complete or fail work. The sender can cancel queued or claimed work; cancellation rejects late results. Owner and agent views use snapshot names so later connection renames do not rewrite history.

The public HTTP API is `/v1/agents` and `/v1/agent-tasks`; MCP exposes equivalent typed tools. Task lists use a stable row cursor with a 100-item page and optional status filter. Owner grant, task and history views are loopback-only under `/api/agent-handoff-grants` and `/api/agent-handoffs`. Task text is limited to 16 KiB. The bridge does not expose management routes. Agent-facing reads are scoped to the authenticated sender or recipient. Events are owner-facing, include one action per transition, and exclude claim tokens.

Delivery is an authenticated pull inbox. `queued` means recorded and available, not that the recipient was awakened, accepted or executed the task. Client-specific wake adapters, agent process liveness, file attachments, result artifacts and cross-agent permission delegation are separate future work. They must be verified against each client product before advertising them. This first slice enables a real, inspectable task exchange without assuming the path used by earlier Grok-to-Codex prompting is available to AgentWay.
