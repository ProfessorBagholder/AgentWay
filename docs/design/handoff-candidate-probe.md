# Candidate receiver probe

Status: implementation branch `feat/handoff-candidate-probe`, 2026-09-24. This is an owner-triggered **test** of one unverified Grok Bot receiver, not automatic-delivery enrollment or native verification.

The owner first saves an active Grok Bot routine POST URL and bearer key on that Bot's receiver setup page. A permitted, authenticated sender then queues a normal pull task for that Bot titled exactly `AgentWay receiver probe` with instructions exactly `Confirm receipt. Do not publish anything.` and a deadline more than 60 seconds away. The owner selects that queued task in the setup page and sends one test. The owner-only POST route verifies the directed grant, exact recipient and task text, current binding generation, saved webhook, and unexpired queued pull state before reserving a durable, unique probe record. It sends a short envelope containing only probe/delivery ID, task ID, kind, binding generation and deadline. It does not send instructions or an AgentWay credential to the webhook.

There is no automatic retry. A 200 from Cursor records `admitted` (a Bot run started); non-200 records `not_sent`; a lost response records `unknown`. A crash after reserving the probe leaves `started` on disk, which the owner status route reports as `unknown` after 30 seconds. The task's unique probe record blocks a second send even if the outcome is uncertain. Rotation or removal fences the pre-send recheck; if a request is already in flight, its native outcome can remain uncertain. The Bot must authenticate separately to AgentWay to claim and complete the **pull** task. The original sender must read and acknowledge the result separately.

The probe API and UI never write `verified_at`, set `ready`, or change discovery or `automatic_delivery`. A provider 200, task completion, or sender acknowledgment alone is insufficient to verify the exact native Bot and idle sender return. The operator must compare AgentWay records with the Bot's native run history and then run the full two-way conformance cases before any receiver is made automatic-ready. The same task, claim, deadline, result and acknowledgment rules apply to all products; this test route supplies only the Grok-specific trigger being evaluated.
