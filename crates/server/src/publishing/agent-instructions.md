AgentWay publishing guidance, version 13.

Read the connection object returned by youtube_status to confirm your authenticated connection ID and its permissions. Credentials identify an AgentWay connection, not a particular conversation or process. Keep each connection's token separate. publish_enabled=false allows discovery and reads but blocks media reservation, uploads and YouTube mutations. Disconnect revokes only that connection. Media belongs to the credential that reserved it; use the same connection for its PUT and publication. The connected channel and publication history are owner-shared; authorized agents can manage existing published videos. Retrying an upload uses its original connection, whose permission is also checked by the worker.

When first using this connection, briefly tell the user which publishing choices you can apply: title, description, visibility (private, unlisted or public), made-for-kids audience designation, and realistic altered or synthetic media disclosure. Explain choices in plain language when relevant to their video. Use the user's existing instructions; ask only for unresolved decisions needed to publish. Do not repeat onboarding on every upload. Revisit guidance when its version changes.

Read youtube_status (HTTP: GET /v1/status) before publishing to check the connected channel and private_only policy. Authenticate every HTTP request, including media PUT, with the connection's bearer token. Never expose credentials in chat or content. Confirm the intended channel from the user's instructions. Do not silently substitute private for requested public visibility.

Use create_media_upload (POST /v1/media with size and mime), then PUT raw video bytes to its upload_path. Do not submit a local path or base64. Supported MIME types are video/mp4, video/quicktime and video/webm; maximum file size is 2 GiB, and the hosting proxy may impose a lower limit.

Use publish_youtube (POST /v1/youtube/publish) with request_id (UUID), media_id, title, description, privacy, made_for_kids and contains_synthetic_media. The supplied publish_schema is authoritative. Title must be 1–100 characters; description is at most 5000 UTF-8 bytes; neither may contain < or >. Description defaults to empty and privacy defaults to private if omitted. Both disclosure fields require explicit JSON booleans; never guess them from the agent or channel name. AI-assisted writing alone does not automatically imply a synthetic-media disclosure. For realistic altered or synthetic content, consult https://support.google.com/youtube/answer/14328491 and resolve uncertainty with the user before submitting.

Subscriber notifications default to on. Set notify_subscribers to false only when disabling notifications for this upload; omit it or send true to enable them.

Video settings: publish_youtube accepts a settings object for category_id, tags, default_language (title/description), default_audio_language, publish_at, embeddable, license (youtube or creativeCommon), public_stats_viewable, paid_product_placement, recording_date and localizations. Offer relevant choices when first discovering this capability, using existing user preferences rather than asking every question for every upload. Choose category_id explicitly from list_youtube_categories (GET /v1/youtube/categories?region_code=CA, or the user's region); omitted category preserves legacy Entertainment (24), not a recommended category. Tags have a combined 500-character limit including commas and two extra quotes for each tag containing a space. Language codes are BCP-47. Localizations is a complete language-keyed map of title/description; {} clears translations. License is an explicit rights decision. Paid promotion is distinct from synthetic-media disclosure; ask when unresolved. Never assume all YouTube Studio controls exist in this API; unsupported fields are rejected.

Scheduling: publish_at must be a future RFC3339 timestamp including timezone and privacy must be private. Resolve the user's timezone before converting it. YouTube handles the scheduled public release; AgentWay does not need to remain running after YouTube receives the upload. The owner's private-only policy prohibits scheduling. Only never-published private videos can be scheduled; YouTube makes the final eligibility decision. Upload privately first if thumbnails/captions must be ready before publication, apply and verify those assets, then schedule or publish. These steps are not atomic; report a failed step without starting another upload.

Metadata edits: get_youtube_video now returns snippet, status, localizations, recordingDetails, paidProductPlacementDetails and etag. Use update_youtube_video (POST /v1/youtube/video-settings) with request_id, publication_id, expected_etag from that read, and only the fields to change: title, description, privacy, made_for_kids, contains_synthetic_media and/or settings. Omitted fields are preserved. Empty description clears it; tags=[] clears tags. settings.clear_schedule=true cancels scheduling; it cannot accompany publish_at. When changing a scheduled video to public/unlisted, explicitly clear its schedule. Existing video-management consent is required. Notifications are an upload-only choice and cannot be changed retroactively. Read actual fields, including disclosures, before claiming they match. Missing fields mean unverified, not false. get_youtube_video also returns contains_synthetic_media as true, false, or null when YouTube omits it. null does not mean the field was not submitted or was rejected; report that YouTube readback cannot verify it. Do not repeatedly rewrite the disclosure to obtain a readback. Tags may be reordered by YouTube; compare their values without depending on order.

A completed settings operation means readback matched. verification_pending means accepted but not yet visible. outcome_unknown means the write might have landed. Retain original request_id and exact arguments; retry after five seconds to READ and reconcile, never to resend. This remains true after restart. A stale expected_etag is rejected before writing. A pending update blocks another settings write to that publication until reconciled. get_youtube_settings_operation (GET /v1/youtube/settings-operations/{request_id}) refreshes YouTube and reconciles the saved operation without writing the video again. Poll no faster than every five seconds. Do not use a new UUID to bypass uncertainty.

Video artwork/captions: reserve media through create_media_upload and PUT raw bytes, then manage_youtube_video_asset (POST /v1/youtube/video-assets). AgentWay's thumbnail/caption limit is 2 MiB. set_thumbnail takes publication_id, request_id and media_id for PNG/JPEG. set_caption takes a timed UTF-8 SRT (application/x-subrip) or WebVTT (text/vtt) media_id; for a new track supply language, name (maximum 150 characters, empty allowed), and explicit is_draft. For replacement supply caption_id and is_draft; omit language/name to preserve them. list_youtube_captions (GET /v1/publications/{id}/captions) returns IDs and processing status; serving means ready, failed includes failureReason. Automatic synchronization of untimed transcripts is unsupported. delete_caption takes publication_id, request_id and caption_id, with user authorization. No media_id is needed for deletion.

Asset operation status=accepted means YouTube acknowledged the write, not that captions finished processing or that the image looks right. outcome_unknown requires inspecting the current thumbnail or caption tracks; do not blindly repeat with another UUID. upload_pending means retry the SAME request_id and identical arguments after five seconds: AgentWay queries/resumes the persisted encrypted upload session, including after restart or a lost completion response. It does not create another caption or re-send completed bytes. Accepted/rejected retries return their saved result. Expired sessions with uncertain outcomes are not silently recreated. get_youtube_asset_operation (GET /v1/youtube/asset-operations/{request_id}) reads that result. After rejection, resolve the stated problem before creating a new request. Thumbnail availability and other feature restrictions are determined by YouTube.

Keep request_id and all arguments identical when retrying the same publication; use a new ID only for a new publication. Read get_publication (GET /v1/publications/{id}) for progress and results; poll queued or uploading jobs no more frequently than every five seconds. Resume interrupted uploads using retry_publication (POST /v1/publications/{id}/retry). Compare actual_privacy with requested_privacy before claiming the requested visibility. A visibility verification error is not an upload failure and must not trigger a duplicate upload. A video URL confirms upload, not completed YouTube processing or Shorts classification. Use get_youtube_video for audience and synthetic-media declaration readback.


Correcting an already published video: the creating agent renders and validates corrected media, including duration and ending. AgentWay does not create or edit the media. Check youtube_status.video_management_authorized before starting a correction batch; if false the owner must authorize YouTube again once in AgentWay to grant editing permission. Do not rotate the agent token or disconnect the channel.

Use list_publications (GET /v1/publications, latest 100) to match existing YouTube URLs to publication IDs if needed. For each correction, keep the original publication ID and a stable new upload request_id. Upload the corrected video privately with notify_subscribers=false. Wait for upload completion, then poll get_youtube_video (GET /v1/publications/{id}/youtube) no faster than every five seconds until ready=true. Processing failure, rejection, missing status or an error is not success. Verify the rendered content yourself; ready=true only establishes YouTube processing.

Call set_youtube_visibility (POST /v1/publications/{id}/visibility) with a fresh stable request_id and privacy=public for the corrected publication. Check the returned operation status: only completed means verified success; interrupted carries an error and may have an uncertain remote outcome. Retry the same request_id and inputs to reconcile. After verifying the corrected video is public, retire the original using that endpoint with privacy=private and replacement_id=<corrected publication ID>. This enforces that the corrected video is processed and public before hiding the original. Keep originals private unless the user has authorized permanent cleanup. With that authorization, delete the faulty original using the deletion operation below. These two changes cannot be atomic on YouTube: briefly overlapping public copies are possible, and a failed retirement must be reported and retried, not ignored.

get_video_operation (GET /v1/video-operations/{request_id}) and list_video_operations (GET /v1/publications/{id}/operations) retain operation outcomes, errors and original/replacement links. Completed results describe the last verified outcome; get_youtube_video reads current state. Never restart a correction by uploading another duplicate. YouTube replacement uploads receive new URLs; these tools do not trim or replace video bytes in place.


Permanent correction cleanup: after user authorization, use delete_replaced_youtube_video (POST /v1/publications/{original_id}/delete) with a new stable request_id, replacement_id=<corrected publication ID>, and confirm_delete=true. MCP additionally takes id=<original publication ID>. The original must already be private; AgentWay rechecks that its distinct same-channel replacement is processed and public before deletion. Do not request redundant authorization for each video when the user already authorized cleanup of the batch. Retry identical arguments with the same request_id after uncertain results; only status=completed means resolved. A missing original before any recorded deletion attempt is not reported as successful deletion. Existing video-management consent covers deletion; do not ask the user to reauthorize solely for this feature. Retain request IDs and original/replacement links for reporting; never delete the corrected video. Completed upload history remains with deleted_at, while the faulty video itself is removed from YouTube.

Channel description: use get_youtube_channel (GET /v1/youtube/channel) to read channel_id, title and description. To apply the user's requested channel blurb, call set_youtube_channel_description (POST /v1/youtube/channel/description) with channel_id, expected_description equal to the exact description just read, and description containing the new text (maximum 1000 characters; empty clears it). The channel_description_schema is authoritative. Existing video-management consent covers this. Other channel settings are preserved. Only status=completed with verified=true confirms readback. Retry identical arguments after uncertain errors; if the description changed, read it again and resolve that change rather than blindly overwriting it. This edits the channel's default description, not localized translations, channel name or individual video descriptions.

Channel description verification: YouTube may accept a write before reads reflect it. AgentWay retries reads for a bounded period. HTTP 202 / status=verification_pending means accepted but not yet verified, not a rejected update. Wait at least retry_after_seconds, then use get_youtube_channel (GET /v1/youtube/channel) and compare the description to your requested text. Do not send another write just because readback is delayed. Identical retries of a pending accepted write only recheck it, including after restart. Report continued mismatch or read errors honestly; never claim verified success until the text matches.


YouTube podcasts: AgentWay can create a show playlist, add existing or newly uploaded full episodes, upload its square cover, and enable YouTube podcast features. On discovery or this guidance upgrade, briefly offer this to users publishing a podcast: "Would you like me to organize your full episodes as a YouTube podcast?" Honor an existing answer; do not ask again per episode. Resolve only missing show title, description, visibility, cover and episode ordering with the user. Do not enable a podcast without their agreement. A podcast is a designated playlist, not a new upload format. Existing video URLs are retained. YouTube Music inclusion and podcast discovery are subject to YouTube eligibility, not guaranteed.

Use list_youtube_playlists (GET /v1/youtube/playlists) to find an existing show before creating one; paginate with page_token=nextPageToken. Supply playlist_id to read its details and episodes. Use manage_youtube_podcast (POST /v1/youtube/podcasts) with request_id (stable UUID), channel_id and one action from podcast_schema:
- create_playlist: title, description, privacy. Save the returned resource.id as playlist_id. This creates an ordinary playlist initially.
- set_cover: playlist_id, media_id. Reserve media with POST /v1/media (size and mime=image/png or image/jpeg), PUT raw square image bytes to upload_path, then set_cover. AgentWay accepts covers up to 2 MiB; 1280x1280 is recommended. This is show artwork, not a video thumbnail.
- enable_podcast: playlist_id. Add the selected full episodes and set the square cover first. Existing playlist title, description, privacy and episodes are preserved.
- add_episode: playlist_id, video_id (YouTube ID, not AgentWay publication ID), full_episode=true, optional zero-based position (omit to append). Only videos belonging to the connected channel can be added. Existing membership is returned without duplication; existing entries are not reordered. Add future completed uploads to the same playlist after verifying processing. Keep Shorts, trailers and excerpts separate from full-episode podcast playlists.

Existing management consent covers these operations. Keep each operation's request_id and arguments on retries. Inspect the result status: completed means YouTube acknowledged the operation (or membership already existed); list the playlist to inspect current state. Rejected includes a provider reason; correct the issue before using a new request ID. outcome_unknown / HTTP 202 means a write might have succeeded: do not generate another UUID and repeat it. List playlists or episodes to reconcile and retain the discovered resource ID; report unresolved uncertainty. Identical retries of playlist creation, designation and episode assignment return the saved outcome without resending the write, even after restart. Cover retries follow the resumable-upload recovery below. get_youtube_podcast_operation (GET /v1/youtube/podcast-operations/{request_id}) retrieves it. Podcast setup is several operations: retain the playlist ID and continue from the last successful step, never create a second show just because a later step failed.


Podcast setup order: create or select the show playlist → add the selected full episodes → set_cover → enable_podcast. add_episode works before podcast designation, so setup never depends on enabling first. If continuing a partially completed v7 setup, reuse the existing playlist_id and ready cover media_id; do not recreate the playlist, reupload videos or reserve another cover. Reuse an operation ID whose failure occurred before any provider write. A saved rejected operation returns its original rejection; after correcting the cause, use a new request_id for that rejected step only. Never bypass outcome_unknown with a fresh ID.


Cover recovery (version 10): set_cover uses a persisted, encrypted resumable upload session. upload_pending / HTTP 202 includes safe error codes and HTTP status where available. Wait five seconds, then retry set_cover with the SAME request_id and identical inputs to query and resume the same session. A lost completion response is reconciled by querying that session, without uploading the bytes again. The operation record updates when the retry verifies completion; merely reading its record returns the last saved state. Legacy version 7/8 set_cover operations stuck at outcome_unknown can also be retried with the same arguments: AgentWay reads current cover resources, updates an existing hero image if present, or starts a resumable upload of the same requested artwork. This is specific to setting cover artwork; never repeat playlist creation or episode insertion with new IDs. If a saved cover session returns 404/410, AgentWay retires that session. Retry the same request_id after five seconds: it re-reads existing hero artwork and starts a replacement session for the same image, updating the existing resource if present. This does not recreate the playlist or videos. After cover completion, retry a previously rejected enable_podcast using a new request_id, since rejected operation IDs retain their original result.
